## 1. Why partners need a new mental model

Most partners pitch ARAG as "ChatGPT for your data." That framing caps the deal size, costs the customer no money to rip out, and loses to every commodity vendor with a free trial. The Sample ARAG App proves something different is on the table.

In a single application, the same KB is used to:

- Stream conversational answers with citation panels.
- Render a SERP-like search experience with AI summaries, dual-KB results, content-type filters, and follow-up suggestions.
- Generate an entire certification program from scratch — name, tagline, pass percentage, prerequisites, knowledge domains, sub-topics, learning modules, exam questions (mixed multiple-choice + free-text), per-question grading, and a final personalized assessment narrative — all from one corpus of markdown.
- Browse a 500-resource library with topic and content-type filters that map directly to Nuclia label paths.
- Drive a **typed knowledge graph** with bespoke entity types (SPEAKER, ORGANIZATION, TECHNOLOGY, STANDARD, CONCEPT…) generated by a data-augmentation agent, with click-to-expand path traversal and hybrid-retrieval-driven "related resources."
- Serve DASH-streamed video with auth-injecting RequestModifiers, blob fallbacks, transcript sync, and timestamp-anchored deep linking — all gated by a single service-account header.
- Drop in as a `<nuclia-chat>` web component on any page with no SDK.

The point: **ARAG is six products in one** — a retrieval engine, a generation engine, a structured-output engine, a knowledge-graph database, a media pipeline, and a widget library. Selling it as one of those six leaves the other five on the table.

This framework gives partners a four-tier capability ladder, a use-case catalog per tier, and a commercial wedge for each step up.

## 2. The Five Primitives

Every customer conversation lands faster when partners can name the five primitives that the platform exposes. The four-tier ladder is built by combining these.

| # | Primitive | API surface | What it actually does |
|---|-----------|-------------|------------------------|
| **P1** | **Retrieve** | `/v1/kb/{id}/find`, `/v1/kb/{id}/catalog`, `/v1/kb/{id}/labelsets` | Semantic + keyword + filtered search across any corpus. Pagination, hybrid mode (`features:['keyword','semantic']`), classification-label filters, icon/mimetype filters, score-ranked paragraph matches with timestamp positions. |
| **P2** | **Generate** | `/v1/kb/{id}/ask` (sync via `x-synchronous: true` or streaming NDJSON) | LLM-grounded answer with retrieval implicit. Streams `answer`, `retrieval`, `augmented_context`, `metadata`, `status` items. Custom prompt templates with `{context}` and `{question}` placeholders. Markdown formatting, query rephrasing, citation extraction with confidence scores. |
| **P3** | **Constrain** | `/v1/kb/{id}/ask` with `answer_json_schema` | Same generation engine, output bound to a JSON Schema. Used in the sample app to generate exam questions, learning module structures, follow-up questions, taxonomy, and program metadata. This is the primitive that turns ARAG into a programmable backend. |
| **P4** | **Reason over relations** | `/v1/kb/{id}/graph`, `/v1/kb/{id}/graph/nodes` | Typed knowledge graph. Nodes by entity group, fuzzy node search, undirected path queries from a source. Critically, queries can filter to `{prop:'generated', by:'data-augmentation'}` — i.e. only the bespoke graph extracted by a custom agent, ignoring default NER noise. |
| **P5** | **Stream & secure media** | `/v1/kb/{id}/resource/{id}`, `.../download/field` | Resource fetch with full bundle (`basic`, `origin`, `extra`, `values`, `extracted`). DASH MPD streaming with auth headers injected on every segment, blob fallback for any field. The platform handles auth — partners don't need a separate CDN. |

Every Tier 2–4 use case is built by composing 2–4 of these primitives in series or parallel. Get partners comfortable naming the primitive before they pitch the use case.

## 3. The Capability Ladder

### Tier 1 — Foundations: Grounded Search & Q&A

> **One-line pitch:** "Replace your dumb search box and your AI chat experiment with a single retrieval-grounded answer engine that cites its sources."

This is the table-stakes tier. It's what most customers think ARAG is. Selling stops here at $30–80K ACV.

**What's in this tier**

- Semantic search with score-ranked paragraph matches (`searchSiteContent` / `searchResources` → `/find`). Returns matched paragraphs with positions, lets you build "jump to the line that matched my query."
- Sync Q&A with citation extraction (`siteContentClient.ask` → `/ask` with `x-synchronous: true`). One round-trip, JSON response, citations with confidence scores attached.
- Streaming Q&A with progressive token rendering (`siteContentClient.stream`). NDJSON parsing of `{item:{type:'answer'|'retrieval'|...}}` events.
- Citation chips and source panels — deduped, ranked, deep-linkable. Sample app builds a session-wide unique source list across multi-turn conversations (`SourcePanel.tsx`).
- Markdown rendering with `prefer_markdown: true` for headers, lists, tables.
- Query rephrasing (`rephrase: true`) — the LLM rewrites the user query before retrieval. Free quality lift, no extra calls.
- The drop-in `<nuclia-search-bar>` and `<nuclia-chat>` web components for partners who can't ship a custom front-end (see `WidgetShowcasePage.tsx` and `snippetData.ts` for live examples with credential injection and Shadow-DOM theming).

**Partner play**

This is the "let me show you in 30 minutes" tier. Use the sample app's `/assistant`, `/search`, and the widget showcase to demo. Win the customer's heart, then immediately discuss Tier 2 — because Tier 1 alone won't be remembered against the next vendor.

Pricing wedge: **bundled with a content-ingestion package**. Sell the engineering hours to ingest the customer's CMS, SharePoint, S3, or wiki — that's where partner margin lives at Tier 1.

### Tier 2 — Multi-Surface Conversational Intelligence

> **One-line pitch:** "One KB. One API. Three different chat experiences, each tuned for a different audience and outcome, with deep-linkable sessions, per-resource context, and embedded widgets."

This is where ARAG starts to look like a platform instead of a feature. ACV doubles when customers see this tier demoed against their own corpus.

**What's in this tier — every pattern is live in the sample app**

- **KB routing by user state.** The same UI swaps `siteContentClient` for `memberKnowledgeClient` based on `useMember()` — a single conditional gates an entirely different answer surface (`AssistantPage.tsx:44`, `FloatingChat.tsx:249`). Same trick works for any tenant, role, language, or geography.
- **Custom system + user prompts with placeholder substitution.** Nuclia supports `prompt: {system, user}` where the user template can include `{context}` and `{question}`. The sample uses this to enforce concise answers, multi-step research analysis, exam-grader rubrics, and CTA-only responses. Five distinct voices, one API.
- **"Research mode" via query prefixing.** Toggling a UI switch prepends `"Provide a comprehensive, multi-source analysis with detailed citations: "` to the raw query (`ResearchAssistantPage.tsx:22`). Re-uses the same `/ask` endpoint — partners don't realise how cheaply this is implemented until they read the code.
- **Resource-scoped chat.** The "ask about this PDF/video" sidebar prefixes the user query with `Regarding the ARAKS resource titled "{title}": …` and uses an explicit per-resource prompt (`ResourceChatTab.tsx:62`). The retriever still has the whole corpus, but the model focuses. Cheap pseudo-scoping — works on tens of thousands of resources without per-resource indexes.
- **Multilingual answers via prompt prefix.** Hard-coded language dropdown injects `Respond in {language}: ` (`ResourceChatTab.tsx`, same in `StudyAssistantChat.tsx`). No separate model, no separate KB, no embeddings retraining.
- **Floating widget with conversion logic.** Persistent chat on every page (`FloatingChat.tsx`), with **prospect-mode and member-mode prompts** that differ in style, length, and **whether they include a sales CTA in the response**. The "STRICT RULES: max 3 sentences, then exactly ONE CTA link from the context, then STOP" prompt is the single highest-leverage piece of code in the entire repo for partners selling to marketers.
- **Field-engineered CTAs.** The site KB has resources with literal `callToAction` text fields and `searchResultDisplay: {title, description}` JSON-encoded text fields. The model reads them out of `{context}`, the front-end converts the model's `[label](href)` syntax into branded CTA buttons (`formatAssistantHtml` in `FloatingChat.tsx:22-45`). **Content design drives marketing performance** — and partners can sell content engineering services on top.
- **Deep-link sharing.** `?q=...` on assistant/research/search pages auto-fires the query exactly once, then strips itself from the URL (`autoSubmittedRef` pattern). `?tab=transcript&t=125.5` on resource detail lands users on the exact second of a video where the answer lives. **Every conversation becomes a shareable URL.**
- **Drop-in web components.** `<nuclia-chat>`, `<nuclia-search-bar>`, `<nuclia-search-results>`, `<nuclia-popup>`, all themable via base64'd CSS injected through `csspath`, branded via Shadow-DOM CSS variables (`--nuclia-color-primary`). The `WidgetShowcasePage` shows the source code copy-paste customers will demand. Three weeks of partner integration work compressed into one HTML snippet.

**Partner play**

This is the *differentiation* tier. Lead with the floating chat's prospect-vs-member prompts. Show how the same KB powers a content-marketing CTA experience for unauthed traffic and a high-detail research workspace for paying users. The KB is shared, the model is shared, only the prompt changes. That's the ARAG "platform" moment.

Pricing wedge: **prompt engineering + KB curation + CTA orchestration** as a recurring service. Three or four distinct chat surfaces per customer at $5–10K/month of managed prompt and content work. Expand inside the account by adding new surfaces (sales engineering chat, support deflection, internal Q&A) without ever leaving the same KB.

### Tier 3 — Structured AI Workflows

> **One-line pitch:** "The same retrieval engine becomes a typed API. Generate a certification program, a quiz, a learning module, a CTA, a comparison table, or a categorised case file — fully type-safe, schema-validated, and grounded in your corpus."

This is the tier most partners don't know exists. It's where ARAG stops being a chat product and becomes a **programmable AI backend**. ACV moves into six figures because customers stop budgeting it against ChatGPT and start budgeting it against a custom platform build.

**The primitive: `askForJson` / `answer_json_schema`**

A single helper (`ragApi.ts:751-875`) sends the query with a JSON Schema in the body and parses `answer_json` from the response. The wrapper auto-injects `additionalProperties:false` at every object level (Nuclia's strict-mode requirement) and falls back gracefully through three response shapes. **Eight different use cases in the sample app are built on this one primitive.**

**Every pattern is live in the sample app**

- **Domain-aware suggestion chips** (`DashboardPage.tsx:117`). Chain: `fetchTopicLabels()` → askForJson with the labelset names baked into the prompt → 5 specific, non-generic suggestions returned as `{suggestions: string[]}`. The KB tells you what the KB is about.
- **Self-describing certification program** (`CertificationContext.tsx:75`). Single askForJson returns name, tagline, pass percentage, duration, prerequisites. The customer's content body becomes the source of authority for the *credential* designed around it.
- **AI-discovered taxonomy** (`CertificationContext.tsx:120`). Returns 6-8 distinct knowledge domains, each with a description. Used to drive domain picker cards, quiz builder, study chat suggestions. The KB tells you its own ontology.
- **AI-designed sub-topics** (`CertificationPage.tsx:84`). Per-domain drill-down, lazily fired on click, cached client-side. A two-layer dynamic taxonomy with no editorial work.
- **AI-designed learning modules** (`CertificationContext.tsx:172`). 3 modules × 5 topics each, with validation guard rails ("modules must each cover different subject areas with no overlap"). The model is asked to be its own curriculum designer.
- **Mixed-shape exam questions** (`ExamPage.tsx:69`). A single schema that contains both multiple-choice (with `options` and `correct`) and free-text (with `rubric`) fields — all marked required at the schema level, but only the relevant set populated per row, with client-side validation pruning malformed rows. Partner-noteworthy pattern: **schema permissive, code strict**.
- **Per-question free-text grading** (`ExamPage.tsx:174`). Iterates each free-text question, streams a grading response per question, regex-extracts the first JSON object. A *manual* structured-output pattern — useful when you want streaming feedback but still want JSON. Both this pattern and `askForJson` are valid; partners need to know when to use which.
- **Composite grading narrative** (`ExamPage.tsx:266`). Free-form markdown stream summarising the whole exam, built from a programmatically composed user prompt (`buildGradingPrompt` in `quizTypes.ts:39`). Mixes per-question grades, MC results, and rubric coverage into one humanised assessment.
- **Schema-constrained follow-up suggestions** (`SearchResultsPage.tsx:33`). The "People Also Ask" panel is one askForJson call with `{questions: string[]}`. Runs in parallel with the SERP results — partners should recognise that schema-constrained and free-form generations can be **fanned out concurrently from one user action**.

**Partner play**

This is the *moat-building* tier. Move the customer from "we want chat" to "we want an AI-driven workflow." The pitch isn't "AI chatbot" — it's "we're going to use your existing content to dynamically generate every UI surface that needs that content as input."

Pricing wedge: **discovery → schema design → workflow build**. A typical Tier 3 engagement is 8–12 weeks at $80–250K to design a half-dozen JSON-Schema-constrained AI workflows that power production features (onboarding pathways, dynamic certifications, intelligent forms, taxonomy generation, content classification, intelligent CTAs).

**Use case starter ideas — group by *workflow*, not by *vertical***

- **Dynamic certification or accreditation programs.** Health professionals, real-estate licensing, IT certifications, internal corporate compliance. The ARAKS demo's whole certification stack (program → domains → modules → exams → grading) can be re-skinned for any industry overnight.
- **Adaptive onboarding paths.** AI generates the right onboarding modules per role/seniority from a single corporate-knowledge corpus. Modules adapt over time as the KB grows.
- **Intelligent CTAs and follow-ups.** Schema-constrained suggestion engine attached to a content site — "People Also Ask," "Next Best Action," "Related Forms" — all driven from the same KB.
- **Automated content classification.** Schema returns `{category, tags[], reading_level, sentiment, compliance_flags[]}`. Run it over an incoming document stream. Tag everything automatically with the same engine that powers search.
- **Adaptive triage / case routing.** Schema returns `{department, priority, suggested_template, missing_information[]}`. Drop in on top of an existing ticketing system.
- **Quote / draft document generation.** Schema returns `{line_items, total, terms, customer_specific_notes}`. The KB is the company's pricing book + past quotes. This is a six-figure deal on its own.
- **Job-description generation.** From the org's actual capability documents, generate role descriptions, key responsibilities, and skill assessments. Same pattern as the certification demo.
- **Auto-generated FAQs.** Schema returns `{question, answer, source_doc_ids[]}`. Customer hands you a policy doc; ARAG hands them back a publishable FAQ.
- **Personalised learning summaries.** Each user's progress + last query + role → schema returns `{topic, three_key_points[], next_resource_id}`. Push as a daily email.
- **Comparison tables on demand.** Schema returns `{columns[], rows[][]}`. "Compare these three products / policies / case outcomes." A grounded, structured artifact the customer can publish.

**Cross-cutting prompt patterns to teach explicitly**

- **Use `{context}` and `{question}` in the user template** — that's how you tell Nuclia where the retrieved context goes and where the user query goes. Without these placeholders, you lose access to retrieval inside the prompt body.
- **System prompt = voice + format**, user template = scaffolding around retrieval. Don't put domain rules in the user template.
- **Verbose generations (long form) — say so in the system prompt.** Conciseness is the default for newer ARAG releases. The phrase "this is the one context where thorough responses are welcome" recurs in the sample app.
- **Schema validation is two-stage** — Nuclia returns the JSON, but partners must validate it themselves (the sample app filters malformed rows from the exam-question schema). Teach partners to treat schema as a *hint*, not a contract.
- **Manual JSON-via-prompt vs schema-via-API.** The exam grader uses a free-form stream with `"Respond ONLY with valid JSON…"` in the system prompt, then regex-extracts. This is correct when you want streaming + structure. When you want one-shot, use `askForJson`.

### Tier 4 — Agentic & Knowledge-Graph Platform

> **One-line pitch:** "Stop indexing documents. Start indexing relationships. ARAG runs data-augmentation agents over your corpus to extract a typed knowledge graph, custom enrichment fields, hybrid retrieval policies, and multimodal field bundles — every one of them queryable through a single API key."

This is the *platform* tier. The "we win this account for five years" tier. Customers commit when they realise they're not just buying a Q&A box — they're buying a structured knowledge layer that lives upstream of every AI feature they'll ever ship.

**What's in this tier**

- **Custom data-augmentation agents.** The graph queries in the sample app filter to `{prop:'generated', by:'data-augmentation'}` (`graphApi.ts:140`). That filter is the entire reason graphs work — it scopes results to *agent-generated* entities and relations only, ignoring the default NER noise. Partners need to understand: **the platform supports running a custom extraction agent over the corpus that produces a domain-specific typed graph**. The sample app's graph schema is bespoke to RAG events — SPEAKER, ORGANIZATION, DEVROOM, TECHNOLOGY, PROGRAMMING_LANGUAGE, PROJECT, TALK, STANDARD, CONCEPT, VENUE, with relations like `presents`, `implements`, `covers_topic`, `compared_with`, `targets` (`graphConstants.ts:1-40`). **Every customer can have their own schema.**
- **Typed graph API.** Three endpoints:
  - Nodes by entity group (`/graph/nodes` with `group` + `top_k`).
  - Fuzzy node search (`/graph/nodes` with `match:'fuzzy'`).
  - Paths from a source node (`/graph` with `prop:'path'` + `source` + `undirected:true`).
- **Bidirectional path traversal.** `undirected: true` plus client-side post-processing that marks incoming edges with a reversed arrow (`EntityDetail.tsx:343`). Partners get full graph navigation without needing Cypher or a separate Neo4j cluster.
- **Incremental graph expansion.** Click an entity, fetch its paths, dedupe-merge into the existing graph view (`KnowledgeGraphPage.tsx:116`). The graph grows organically as the user explores.
- **Entity → resources lookup with hybrid retrieval.** `searchRelatedResources(entityValue)` is the single point in the entire app that explicitly sets `features: ['keyword', 'semantic']` (`graphApi.ts:179`). The graph entity becomes the query string; ARAG does the cross-modal lookup that maps a concept to the documents discussing it. This is the bridge between graph and unstructured retrieval — partners should call this out by name.
- **Custom indexed fields harvested at retrieval time.** The sample app's KB stores three custom JSON fields per resource as text fields: `videoinfo`, `searchresultdisplay`, `calltoaction`. The platform delivers them as part of normal retrieval. The front-end pulls them out of `{context}` and uses them directly to drive UI copy, descriptions, and conversion CTAs without ever calling the model (`ragApi.ts:1212-1263`). **This is content engineering as a billable service.**
- **Multimodal retrieval and replay.** Video utterances are reconstructed from `data.files.*.extracted.metadata.paragraphs` with `start_seconds[0]` and `classifications` per paragraph. Search matches return a `position.start_seconds[0]` that becomes the deep-link timestamp. The transcript pane click-to-seeks the video, the video time-update highlights the transcript line — all driven by ARAG's extracted-metadata output (`ragApi.ts:1058-1137`, `KnowledgeDetailPage.tsx:95-102`).
- **DASH adaptive streaming with auth.** `dashjs.MediaPlayer` configured with a custom `RequestModifier.modifyRequestHeader` that injects `X-NUCLIA-SERVICEACCOUNT: Bearer ...` on every segment fetch (`VideoPlayer.tsx:131-142`). The platform handles bandwidth-adaptive video without partners needing a separate CDN or DRM layer.
- **Composite retrieval — generation falls back to discovery.** The exam-results study guide streams an answer first, and **if the streamed answer returns no citations, fires `searchResources()` as a fallback** to synthesise pseudo-citations from a `find` query (`ExamStudyPanel.tsx:84-101`). This pattern — generate first, retrieve second only if needed — is the foundation of true agentic RAG. Partners can extend it: generate → if low confidence then retrieve more → re-ask with augmented context.
- **Labelset-driven filter composition.** Topic filters become Nuclia filter strings: `/classification.labels/{labelset}/{label}`. The labelset name is discovered at runtime (`fetchTopicLabels` falls back across `key-topic` then any non-empty labelset). Content-type filters are icon-path strings: `/icon/video`, `/icon/application/pdf`. Filters can be **stacked freely** — content type AND topic AND any other label.

**Partner play**

This is the *strategic-account* tier. The customer commits to ARAG as the system of record for unstructured + relational knowledge for their organisation, not just for one feature. Expect a 9–18 month sales cycle, $500K–$2M ACV, and a multi-year roadmap.

Pricing wedge: **agent design + schema architecture + ongoing graph curation**. Initial engagement is the design of the data-augmentation agent (entity types, relation types, extraction rules), KB schema (custom fields, labelsets, content-type taxonomy), and ingest pipeline. Recurring revenue is in graph quality monitoring, agent retraining, schema evolution as the customer's vocabulary changes, and net-new use cases bolted on top of the same graph and KB.

Question: "What breaks if we kill service X?" — answer streamed in plain English with a graph visualization underneath. Sold as an internal observability product to platform-engineering orgs.

## 4. Cross-cutting capabilities (apply at every tier)

These aren't a tier of their own — they cut across the ladder, and every tier-1-and-up partner should be able to discuss them confidently in a customer meeting.

### 4.1 Gating & monetisation patterns

The sample app implements seven separate gating patterns, all driven from a single `useMember()` boolean. Partners selling to media, publishing, association, and content-marketplace customers should walk through each:

- **Page-level gates** — full-page interstitial before any ARAG call (e.g., Research Assistant).
- **Answer-content gates** — show first 3 sentences of a streamed answer + blur + "Join to unlock" CTA. Built in `MessageBubble.tsx:42-50`.
- **Citation gates** — citation chips render locked variants with popovers (`CitationChip.tsx:27-61`).
- **Search-result gates** — first N results clear, next M blurred behind a CTA overlay (`SearchResultsPage.tsx:432-457`).
- **Source-card gates** — blurred title/excerpt for non-members.
- **Teaser injection** — every Nth assistant message for prospects becomes a synthetic "Join ARAKS" row (`FloatingChat.tsx:310`).
- **Frontmatter-based content gates** — `access_level: member` in YAML frontmatter triggers a 2-paragraph teaser + overlay on static content pages (`ContentPage.tsx:60-76`).

The gating engine is **front-end logic** — the same KB and the same API are used either way. Partners can build a freemium-to-premium funnel without re-architecting their AI layer.

### 4.2 Deep-link & shareability

- `?q=...` on chat / research / search pages — auto-fires the query once, then strips from URL via `autoSubmittedRef` + `navigate({replace:true})`.
- `?tab=transcript&t=125.5` on resource detail — lands user on the exact second of the matching speaker line.
- `searchResources()` returns `matchTimestamp` extracted from `paragraphs[bestScore].position.start_seconds[0]` — search results carry users directly into the video at the moment the answer lives.

Every conversation becomes shareable. Every search result is a citation-grade deep link. Every assistant answer is a URL.

### 4.3 Prompt engineering patterns to teach explicitly

| Pattern | When to use |
|---|---|
| `system` only | Voice control, format control, length control. Fastest. |
| `system` + `user` with `{context}`/`{question}` | When you need fine control over how retrieval is injected. |
| Query prefix only | A/B-able verbosity ("Research mode"), language switching ("Respond in French: "), resource scoping ("Regarding the resource X:"). Cheapest. |
| `answer_json_schema` | When the response feeds an API, a UI, or another ARAG call. |
| Manual JSON via system prompt + regex extract | When you need streaming + structured output. |

Teach partners to **start with system-only**, escalate to user-template when retrieval injection needs control, escalate to schema when the next consumer is code.

### 4.4 Field engineering as a billable service

The sample app proves that **content design drives prompt design.** The `callToAction`, `searchResultDisplay`, and `videoInfo` fields are JSON-encoded text fields stored alongside resource content; the retriever pulls them in as part of `{context}`; the model is instructed to use them; the front-end intercepts the model's `[label](href)` output and converts it into branded CTAs.

This means partners can sell **ongoing content-engineering services** — designing custom fields per content type, training authors to populate them, monitoring how the model uses them, A/B-testing CTAs by re-editing the source content (no code deployment required). It's the most under-recognised recurring-revenue stream in the platform.

### 4.5 Multilingual without re-indexing

A single hard-coded language dropdown + a `Respond in {language}: ` query prefix delivers multilingual answers from a single KB (`ResourceChatTab.tsx:14`). Works for any language the underlying LLM supports. **No separate KB, no separate embeddings, no separate model.** Partners selling into multinational accounts: lead with this.

### 4.6 Composite RAG (the entry point to agentic patterns)

The exam-results study guide is the cleanest example: `stream()` first; if the stream returned zero citations, fire `searchResources()` and synthesise pseudo-citations from the find response. **This pattern generalises** — "generate, evaluate generation, retrieve more if needed, re-ask with augmented context" is the recipe for true agentic RAG. Partners ready for Tier 4 should be sketching this pattern on a whiteboard, not just demoing it.

## 7. The repo as a teaching artefact

The Sample ARAG App repo itself is partner enablement material. Partners should be told:

- **Read `src/lib/ragApi.ts` first.** Every API endpoint the platform exposes is wrapped here in plain TypeScript. The whole client surface is 1,661 lines — readable in one sitting.
- **Read `src/lib/graphApi.ts` next.** Graph queries, filtering tricks, hybrid retrieval — 243 lines.
- **Use `src/pages/ExamPage.tsx` as the canonical Tier 3 reference.** It contains six distinct generation patterns (taxonomy, sub-topic, schema-MC, schema-FT, manual-JSON streaming grader, free-form composite grader) in one file.
- **Use `src/components/chat/FloatingChat.tsx` as the canonical Tier 2 reference.** Prospect vs member prompts, CTA post-processing, link interception, teaser injection, blur-gate.
- **Use `src/pages/KnowledgeDetailPage.tsx` as the canonical Tier 4 reference.** Video + transcript + resource chat + deep link + utterance highlight — all wired through a single `getResource()` call.

The repo is private at https://github.com/jaysanderson/Sample-ARAG-App. When you give a partner access, give them this framework with it.
